# Engine notes (Romania mod)

Addresses are virtual addresses in `riseofnations.exe` (Steam EE, timestamp 6674863F), from `sbl/rise_z.map`. The code is `camera-smooth/src/romania.c`. Found 2026-10-26.

## 24 nations are compiled in

- The PDB (`sbl/rise.pdb`) has `enum TribeIndex`: AZTECS 0 ... PERSIANS 23, `NUM_TRIBES` 24, then `RANDOM_TRIBE` 24, `RANDOM_OFFENSIVE` 25, `RANDOM_DEFENSIVE` 26, `RANDOM_ECONOMIC` 27, `RANDOM_XPACK` 28. The setup combos use these as item ids and the setup / leader data stores them as the nation until `Game::init_tribes` picks one. (Enumerators can be read from the PDB: the LF_ENUMERATE records are `02 15 03 00 <value u16> <name>\0`.)
- `Tribes` (global 0x00E7FA20, data pointer at +0x14, i.e. `[0x00E7FA34]`) is an `ObjectArray<Tribe>` of 0x5F0-byte entries. `Tribes::Tribes` 0x006F12C0 (a static constructor) allocates **25**: slot 24 is the "Random" pseudo-nation; `Tribes::init` names it from internal string 0x7D00 (`add ecx, 0x8E98` = slot 24 + 0x18, the name).
- `Tribes::init` 0x006EF430 reads rules.xml `<TRIBES>` and refuses any count but 24 (`cmp [ebp-0x38], 0x18`, then an error box); its two loops end at 0x8E80 (24 x 0x5F0).
- Tribe fields: +0x4 file, +0x18 name (`Tribe::get_name`), +0x2C key, +0x54 **power tribe** (whose nation power this nation has; set to its own index), +0x58 barbarian / substituted, +0x60/+0x64/+0x68 backup build, build and unit style (`get_text_num` of BACKUP_BUILD_CONTINENT, BUILD_CONTINENT, UNIT_CONTINENT, so "1 NEuro" reads as 1), +0x70 a 0x160-int map of unit types (identity at load).
- A Romanian player has tribe 24; slot 25 becomes "Random". So: 26 slots (constructor), count 25 and loops to 0x9470 in `Tribes::init`, "Random" written at 0x9488, `Tribes::find` to 0x9470, and every Random id + 1. The full list of patched instructions is `k_patches` in romania.c; all were checked against the exe bytes.
- Places that treat ids 24..28 as Random (all patched): `Game::init_tribes` 0x0058A600 (`cmp edx, 0x18` real nation or Random; `lea eax, [edx-0x19]` + jump table `$LN396` 0x0058AB4C for Offensive / Defensive / Economic / X-Pack; plain random is `Random::get() % 24` in five places), `SetupWin::setup_combos` (the five Random items pushed as 0x18..0x1C, the nation items by a stride loop, the default selection 0x18), `SetupWin::update_interface` 0x005B5A5E, `make_combo_change` 0x005BA66E / 0x005BA8EB, `process_check_change` 0x005BBAC7 / 0x005BBB0F, `on_pulldown_change` 0x005C33B5 and `on_combo_move` 0x005C380E (the Random tooltips: `cmp 0x18` + `lea [reg-0x19]` switch), `PlayerProfile::load` (XPACK_QM_TRIBE and xpack_last_tribe default 0x18).
- The themed random lists in `Game::init_tribes` are jump tables: Offensive `$LN397` 0x0058AB5C (`% 10`), Defensive `$LN398` 0x0058AB84 (`% 7`: Maya, Koreans, Chinese, Russians, Indians, Persians, Iroquois), Economic `$LN399` 0x0058ABA0 (`% 13`), X-Pack `$LN400` 0x0058ABD4 (`% 6`). Each case is `mov [esi + 0xE3A39C], tribe` / `jmp 0x0058A995`. romania.c gives Defensive an eighth case (a copy of the table in its own memory, a stub storing 24, `mov ecx, 8`, `cmp edx, 7`).
- Other loops over all nations (stride 0x5F0 to 0x8E80, patched): `Game::walk_rules_data` 0x005895E6 (saved games and checksums), `Game::log_rules_data`, `GameReportWin::exec` (twice), `UnitBalance::init` (with its not-found `cmp ebx, 0x18`).
- Left at 24 (Romania is not in them): the scenario editor (`IFaceEditorNations::init`), quick match (`GameSpyQuick::pre_modal`), Conquer the World (`ConquestCountries`, `ConquestMapLoader`, `ScenarioFuncSet::set_nation_name`).
- Safe without a change: `IStatsAndAchievements::IncrementStatForNation` and `Unit::explore_goody` check `tribe < 24` before indexing `gNationStatSuffix` (Steam stats per nation; Romania counts for none). `JukeBox::shuffle` picks music by nation with `ja default` for > 23. `Tribe::parse` (the help numbers) switches on the power tribe with `ja default`. `Types::finalize_grafting` 0x00669840 builds the barbarian mask with a loop unrolled by 6 over 24 nations: Romania is not barbarian, so bit 24 stays 0 as it should.
- Many other `0x18` / `0x8E80` immediates are unrelated: struct sizes, combo id ranges (8..15 nations, 16..23 colours), string table offsets (the internal string table is 0x14 bytes per entry, so 0x8E80 is also a string; `tools/istr.py` names them).
- `Tribes::walk_data` saves the array with its count; a game saved before the mod has 25 slots, so "Random" (slot 25) is missing when it is loaded with the mod. Not tested.
- The patches must be in before the static constructors, so romania.c runs from `DllMain` (install_hooks), like the other modules.

## Nation masks

- `TRIBE_MASK` in unitrules, buildingrules, techrules and craftrules is a string of 0/1 read by `String::binary` 0x00A1B080 (high bit first, any length); the type's mask is at +0x10. Availability is `1 << tribe & mask` (`LeaderData::tribe_can_type` 0x006D9380). With 24-character masks bit 24 is 0 everywhere, so Romania would have nothing: every mask gets a 25th character.
- Unit lines: a unique or a regional look of a unit names the generic one in `<GRAFT>`; `Types::finalize_grafting` takes the generic away from the nations that have a member of its line. Same `<NAME>` = the same unit in other art (Tank, Fighter, ...); another name = a unique unit (Cossack, Legions, ...).

## Nation power

- Every nation power is asked through `LeaderData::has_tribe_bonus(int tribe)` 0x006E1370 (thiscall, `ret 4`): 0 when nation powers are switched off in the game rules (`[gamec+0x20] & 4`) and in a few other cases, 1 when the tribe's bit is set in the leader's bit array at +0x6D94 (24 bits, +0x6D88 its size; Conquer the World bonus cards), else `tribes[leader tribe].power_tribe (+0x54) == tribe`. About 320 call sites, each one piece of one nation's power (`push <tribe>` / `call` / `test eax, eax`).
- romania.c hooks it: for a Romanian player (tribe at leader +0xC is 24) it answers 1 at the return addresses listed in `k_bonus`, but only when `has_tribe_bonus(24)` itself is 1 (so "no nation powers" still works). Other players go straight to the original (first instruction of the hook compares the tribe).
- Russian sites (13): 0x00623AB9 plunder stays with the owner; 0x00644E9D Stable units +25% vs supply and siege; 0x0066496E Spies half price; 0x006B0F3A borders +1 per Civic research (its `push 0xd` is 17 instructions before the call); **0x006CDF32** attrition x2 in their territory (`calc_attrition`, asked of the territory owner); 0x006DB03D **Oil** +20% (`calc_resource_bonuses`); 0x006DB90F Refinery without Electronics; 0x006DEA98 borders refreshed on a new age; **0x006DF58F** attrition techs 0x254-0x257 free; 0x006E4694 a free Civic research at start; 0x00733ECB capture loot to the old owner; 0x006DC451 RUSSIAN_COMMUNISM (0, off); 0x0078C86F Conquer the World.
- Roman sites (15): 0x00624D9B free Heavy Infantry with a Barracks; 0x00639A56 / 0x00639B0C fort and tower range (+0, no effect); **0x0063D6E9** Forts 50% faster (Forts only); 0x0063F126 fort and tower hit points (+0%); 0x00650EF8 / 0x006649BB Heavy Infantry faster / cheaper; **0x00665E55** Forts **and Towers** 25% cheaper; **0x006B0EC8** fort borders +3; 0x006D59A0 cities +10 Wealth; 0x006D705F / 0x006DB9A6 Forts and Towers need only their age; **0x006DF6D5** the Fort's research free (0x247-0x249, 0x251-0x253); 0x006E473E a free Military research; 0x0078C91B Conquer the World. Also `Leader::random_personality` 0x006D000E compares the tribe with 6 directly (AI personality field +0x6E04 = 1).
- Korean sites (11): 0x005AB33A extra Citizens at start; 0x005AB801 start with a Temple; 0x005EE79F / 0x005EEF03 / 0x0064C2AA repair and build under fire; 0x006253E0 Citizens with new cities; **0x00665D85** Towers 33% cheaper (left out for Romania: with the Roman discount Towers would cost half); 0x006DB94C Temple without preqs; **0x006DF244** Militia 0x42, Minuteman 0x43, Partisan 0x44 gained as soon as their age comes; 0x006DF2FC Religion techs free; 0x006DF39F tax techs (off). `KOREAN_START_CITIZEN` / `KOREAN_FREE_CITIZEN` are never read; `KOREAN_CITIZENS` is.
- Constants (rules.xml) are at `[0x00C061E4]` (const) = `[0x00C061F0]`: RUSSIAN_* 0x74C-0x774, ROMAN_* 0x5FC-0x638, KOREAN_* 0x7B0-0x7E4.
- In these resource-rate arrays the order is 0 Food, 1 Timber, 2 Wealth, 3 Knowledge, 4 Metal, 5 Oil.
- The help text is `TRIBE` + power tribe in help.xml (`Tribe::say_nation_power` 0x006EFC10): `TRIBE24` for Romania, written by build_data.py with the numbers taken from rules.xml ($NUMBER fields would stay empty: `Tribe::parse` has no case for 24).

## Unit names and icons per nation

- A type's names (`Type`): +0x60 the internal name (rules.xml `<NAME>`, what PREQ / GRAFT / scripts look up), +0x74 the shown name (`Type::lookup_display_name`, from typenames.xml, so localized: display only), +0x88 the graphics family, +0x9C the help name, +0xB0 the type name. `Type::set_name` 0x00663AE0. +0x4 is the type index. Types by index: `[[0x00C0A274] + 4 * index]`; units are 0x32 to 0x191.
- `TypeData::say_name` 0x006677C0 copies +0x74. `UnitData::say_name` 0x006108A0 (object vtable +0x10C) is the selected unit's name (`IFaceSelected::draw_unit_name` 0x00820FF0); for Merchants (0x3D, 0x3E) and 0x190 it builds a name of its own. Objects: +0x9 owner, +0x18 the type.
- Icons are per player and per type: `GraphicPieces::update_all_icons(player, tribe)` 0x0090D3F0 (called by `Game::init_rules_and_teams`, `Setup::build_game`, loading a game, the scenario editor) fills, for each unit type and player p, 3 entries (slot s; probably the icon of ages 1-3, 4-5 and 6-8, from unit_graphics.xml `-AGE0` / `-AGE3` / `-AGE5`, which only some units have, as the Citizens: inferred, not traced) from the player's unit style: byte texture index at type +0xF0 + 3p + s (the index of `tex_id` in the interface texture list `NamedObjectArray<IFaceTexPacket *>` 0x00EBD1C4, `find` 0x00459850), the `tex_id + "_HALF"` texture at +0x108, `tex_col` +0x120, `tex_row` +0x138, `tex_x` / `tex_y` shorts at +0x150 / +0x180 + 6p + 2s, `tex_clip` +0x1B0. It reads the player's unit style only for tribes below 24 (`cmp eax, 0x18` at 0x0090D4F1, patched).
- The 3 icon slots follow unit_graphics.xml's graphics tiers AGE0 / AGE3 / AGE5 (ages 1-3, 4-5, 6-8): the Supply Wagon's SUPPLYWAGON-DEFAULT-AGE0 and -AGE3 have the wagon cell (TEX_UNITS_2, 0, 2), -AGE5 the truck (1, 2), so the game's own Supply Wagon icon turns into a truck in the Industrial Age. romania.c's [late] entries leave the slots from their age on to the game (2026-10-29; still to see in game that slot 2 is the one shown from age 6).
- A player's current age: per-player state `[leader + 0x6EB8]`, `+0xDC` = age ^ 0x62766 (0 = Ancient .. 7 = Information), as entrench.c and nation_art.c read it.
- Icon pages: 512 x 512, cells 61 x 39 every 62 x 40, 8 x 12 (the `_HALF` page 256 x 256, 30 x 19 every 31 x 20). The interface textures are the `IFACETEXLOAD` list at the top of Data\interface.xml; added ones are found by name like the game's.
- romania.c wraps `update_all_icons` (Romania's icons for Romanian players, then the shown names for the player at this computer, `[[0x00C06210] + 0x298]`) and `UnitData::say_name` (the owner's names for a selected unit). Types that share an internal name (Tank, Fighter: the same unit in other art) all get the Romanian name and icon.
- Also found: the setup screen parses a nation's tooltip numbers (`Tribe::parse`) only for ids up to 23 (0x005C348B, 0x005C38FA, patched to 24).

## Music

- `JukeBox::init_game` 0x0097DDC0 reads `Data\sound.xml` (string 0x16620): in the first `<TRACKS>` it looks for a `<TRIBE tribe="...">` whose `tribe` equals the local player's nation name (`Tribe` +0x18, "Romania"), else the one named "default" (the only one the game has). In it, `<AGE age="n">` (n = 0..7, 0 = Ancient) with `<MOOD mood="...">` lists (ECONOMIC, BATTLE_VICTORY, BATTLE_DEFEAT) of `<SOUND file=".\sounds\tracks\x.wav"/>`; `JukeBox::add_track` 0x0097D1B0 files each in the table at 0x00ECBA70 by (age, player, mood).
- `JukeBox::shuffle` 0x0097CC90 starts at the current age's list and steps down to the nearest earlier age that has tracks. So an `<AGE>` list replaces the earlier ones from its age on; the game's single `age="0"` serves every age.
- `JukeBox::shuffle(int, int, int)` also has a switch over the player's tribe (0..23, `ja` past 23) for something else (it was the first lead, 0x0097CE37); not needed for the lists.
- Mood changes (why a track is cut in the middle): the JukeBox is the global `juke_box` 0x00ECBA10; +0x10 (0x00ECBA20) the current mood, +0x1C (0x00ECBA2C) the next mood, +0x20 (0x00ECBA30) the time the track started (`timeGetTime`, set in `JukeBox::play`). Moods: 0 ECONOMIC, 1 BATTLE_VICTORY, 2 BATTLE_DEFEAT. Callers write the next mood and, if it differs from the current one, call `JukeBox::set_next_mood` 0x0097D5D0 (LTCG: the mood in `ecx`): `Leader::process_event_frame` (+0x2CD, 0x006EC44D: during fighting, the local player's score against the best enemy score, above 4/3 victory, below 3/4 defeat), `Leader::lost_a_city` (0x006DC721, 0x006DC855: defeat), `Build::activate` (0x00625B2D), `ScenarioFuncSet::set_music_mood`.
- `set_next_mood` does nothing if the track started less than 30 s ago (0x7530 ms), else calls `shuffle(player, age, mood)`. In `shuffle` the third argument is the mood: for 0 (back to ECONOMIC) it waits until the current track has ended (0x0097CD5D: 6 s since the start, then the sound's vtable +0x58 "still playing"); for 1 or 2 (`jne 0x97cd9b` at 0x0097CD5D) it skips that wait and starts a battle track at once, cutting the one that plays. So fighting starts or the score balance flips -> the music changes mid-track, at most every 30 s. `shuffle` copies the next mood into the current one (0x0097CDA2) when it picks a track, so if the jump is removed the change still happens, at the end of the track.
- The game's tracks are WAV, PCM, stereo, 16 bit, 22050 Hz, only `fmt` and `data` chunks, mean loudness about -16 to -18 dB. Files only in `mod_override\sounds\tracks\` are found (the override's file hooks).

## Units of a nation's own (GRAFT)

- `UnitType::init` (0x0061BB45..0x0061BC19): a unit whose GRAFT names a generic one (`+0x25C`, the generic's type index) is written into each nation's map (`Tribe` +0x70: an int per unit type from 0x32, the type that nation builds for it) for every bit of its TRIBE_MASK (`+0x10`), in a loop unrolled 4 x 6 = 24 nations (stride 0x23A0). Its third pass (0x0061BCA0, also 24) maps the generic's other looks to the nation's own unit. `Types::finalize_grafting` 0x00669840 (after loading the rules and after loading a saved game) then takes the generic away from the nations whose own unit replaces it. Romania (bit 24) was skipped by both loops: it lost the generic and never got its own, so it had no unit wherever it follows another nation's look (tanks, aircraft). romania.c hooks `finalize_grafting` and writes Romania's entries first, both passes.
- A nation's own unit in the files: FLAGS gets `y` (the unique-unit flag 0x1000000 at type +0x2B4), GRAFT names the generic, TYPENAME the name typenames.xml shows (found by a hash of the name), FROM / JUMP the tiers before and after (the generic ones work: Romania's lines mix its own units and generic ones, like the Spanish Tercios). New types are impossible, so build_data.py copies them into campaign-only slots (WHERE None, empty mask), keeping each slot's internal name and changing only its shown text in typenames.xml (as the Airdrop mod does).

## Loading screen

- The loading screen lists the local player's unique units (`FLAGS` with `y`, 0x1000000 at type +0x2B4, that `tribe_can_type` allows): `LoadingWin::prepare_unique_list` 0x00836830 fills a list at +0x4B4 (count +0x4B8, data +0x4C4) and a count at +0x4D0. Each entry takes the next `IFACERECT name="unique_rect"` of the layout (interface.xml has 8, two columns of 4) through the window's find-by-name with a counter.
- `LoadingWin::on_mouse_move` 0x00836AC0 walks +0x4D0 and reads the rect without a NULL check: with more than 8 uniques the 9th is NULL and the game crashes (access violation at 0x00836BA6) as soon as the mouse moves on the loading screen. Romania has more than 8 (2026-10-26 crash). romania.c wraps `prepare_unique_list` and cuts both counts to the rects there are (`UNIQUE_RECTS`).
- The list is in Age order (an outer loop over the 8 Ages, type +0x278). Romania has 11, so `build_data.py` (`unique_rects`) rewrites the layout to 12 rects, 3 per row and 4 rows, filled row by row (`POSITIONING inc_y` around rows of `inc_x`); 136 wide fits "Vanatori de Munte" under its icon. `UNIQUE_RECTS` in romania.c is 12 to match.
- `LoadingWin::draw_special_unit_info` 0x00835330 draws each entry's icon from the type's player slot 0 of the local player (`[types+0x14][t]` +0xF0 + 3p texture, +0x120 column, +0x138 row) and its shown name (+0x74). The screen comes up (`LoadingWin::exec` 0x00836FA0) before `Setup::build_game` calls `GraphicPieces::update_all_icons`, so Romania's own units showed the icons of the generic units their slots were copied from (Phalanx for Falxmen, ...). The `prepare_unique_list` wrapper puts the local Romanian player's icons in first (2026-10-26 report).
- The same report had a second cause: romania.c kept at most 160 matched unit types (`MAX_UNITS`), and with every art variant matched by internal name the list filled before the campaign slots (335..349) that hold Romania's own units. Log: "160 unit types with a Romanian name or icon". Now one entry per unit type.


## Aircraft models (IAR-80, 2026-10-28)

- `fighter_p40.bh3` (224 vertices, 260 triangles) is in game axes: X the wingspan (-57.7 .. 57.7), Y the length with the nose at -Y (-43.9 .. 70.7), Z up (-11.7 .. 18.4). Unlike the vehicles and the chopper, no axis-swapping root node: the renderer in `roman-units/tools/bh3_render.py` (Z up) draws it upright, while vehicle models (`panzer.bh3`, `tankdestroyer.bh3`) come out on their side or upside down.
- Its nodes: `root` (all 224 vertices, position (0, 7.75, 0)) -> `ammo node 0` / `1` (wing guns: `FighterMuzzleFlash` and `Tracer` events), `front body` -> `ammo node 2` (the propeller: `B-25Prop0` / `Prop1` discs) -> `prop end`, `smoke node 0` / `1`. Animations: `Fighter Move`, `Fighter Attack`. Texture 256 x 256, player colour = alpha 57 (grey RGB). The graphics entry scales the model 0.765.
- Sounds go by graphics family (`soundtypes.xml`, `<FAMILY>`); the P-40 family has no entry of its own, so the game presumably falls back on the line's `<FIGHTER>` (inferred, not traced). A unit given another family gets that family's sounds, so the IAR-80's `BARBARIANJAVELINEERS` was filled with `<FIGHTER>`'s. The same for the help text (`help.xml` `<ENTRY name="FAMILY">`).

## Tank models (R-2, 2026-10-28)

- A tank is one mesh whose parts are vertex runs on their own nodes. `panzer.bh3` (395 vertices): `root` (quaternion (-0.5, -0.5, -0.5, 0.5), the axis swap) -> `body1` (vertices 0..262, the hull) -> `body` -> `turret` -> `pivot node 0` (263..359, the turret, which the game turns toward the target) -> `turret top` -> `Dummy03` (360..394, the gun: the recoil) -> `Ammo Node 0` (the shot and the muzzle flash), and `top gun 1` -> `top gun`; `smoke node 1` / `2` (exhaust) under the root. `tankdestroyer.bh3` and `armoredscoutcar.bh3` add one node per wheel (`DummyNN`, runs of 42 or 28 vertices). `lighttank_mkiv.bh3` (Romania's Light Tank until the R-2) has the same turret chain on a sponson.
- **Each run is stored in its node's own frame.** A child's frame = the parent's, moved by the child's position (turned by the parent) and turned by the **conjugate** of the child's quaternion: `R_child = R_parent * M(conj q)`, `t_child = R_parent * p + t_parent`, vertex in the model = `R_node * v + t_node`. Checked by putting the Panzer together both ways (the plain quaternion gives a broken tank, the conjugate the right one). In the model frame: X width, Y length with the front at -Y, Z up from the ground (Z = 0), like the aircraft.
- The tank animations (`mediumtank_default.bha`, `mediumtank_attack1.bha`, ...) have one track per node in the same tree order, with identity quaternions and zero positions at rest: they are offsets from the model's own pose, so a new model may move its nodes (the R-2 moved `pivot node 0`, `Ammo Node 0` and the smoke nodes).
- `romania/tools/build_tank_bh3.py` does this for the R-2: hull on `body1`, turret on `pivot node 0`, `Dummy03` empty (no recoil), nodes moved to the R-2's turret axis, muzzle and exhaust. The cut between hull and turret (`tools/make_tank.py`) is a plane over the superstructure roof, closed with caps on both sides; both parts have 0 open edges after the cut and after the reduction.
- **Vertex limit (2026-10-29).** In Modern Age with R-2s around, the game stopped on "too many verts for Pre-Transform Batch Transform" (BHG RTS run time error, "Safe to Ignore: UNLIKELY"). The text is `internal_strings.xml` entry 6884 (hash 10886666, offset 0x219D0 in the int_str array). It comes from 0x0091D340, a virtual method of the "Pre-Transform Batch Transform" render method (its name and method table near 0x00B55568): the batch has 3 slots (stride 0x1C, count at slot +4, starting at `this` +0xC); a mesh goes into the first slot where count + its vertex count (mesh +0xC) stays under 0x3FFF (16383), and if none has room the error comes up and the mesh is not drawn. When the slots are emptied was not traced (per frame or per draw group), so the safe rule is to keep new models near the game's own sizes: tanks about 400 vertices (`panzer.bh3` 395), the largest original `battleship.bh3` 1223. The R-2 had 1962 (UV seams nearly double a triangle count: 1626 triangles), 8 per slot; it is now 815 (`make_tank.py ... drop`, 624 triangles). The IAR-80 has 477, the Chinook 602.
- Reducing the hull with topology preserved stops near 1000 triangles (the running gear has many holes) and turns the flat cap into a star of slivers; without it the hull goes to 900 triangles with 0 open edges and looks right.
